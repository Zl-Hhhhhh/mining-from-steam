# Embedding 模型选型：BGE-M3

决定日期：2026-11-05。由用户阅读 Jina/BGE-M3 真实评论近邻对照后确定。Step 1–2 的模型选择已完成；这不是全员独立主题核验，也没有完成正式主题体系或模型准确率评估。

## 选择与取舍

正式采用 `BAAI/bge-m3`，固定修订 `5617a9f61b028005a4858fdac845db406aefb181`。

用户的判断是：Jina对中等长度、主题明确的文本有可取之处；BGE的跨语言句意对齐和短句表现更符合本项目的中英文评论比较需求，因此综合选择BGE。

Pilot使用相同600条真实短评、40句构造中英语义对照和12个表达例子。在40次构造句的跨语言方向检索中，BGE第一名命中40次，Jina31次；CPU编码耗时分别约75秒、133秒。构造句不是独立人工金标准，不能将这些数值报告为Steam主题准确率。真实近邻仍有只按泛赞/泛骂靠近的例子，后续需要人工主题核验。

Jina聚类专用版和MiniLM结果保留为历史试验，暂不再生成它们的全量向量。原Pilot的`winner_selected=false`是试验生成时的历史状态，保留不改；后续用户决定以本记录和 `config/embedding_model_selection.json` 为准。

## 固定使用方式

- 使用dense向量，1024维，单位化；CLS池化，显式空前缀，与BGE Pilot一致。
- 本地CPU、float32、4线程；批量最多8条，按实际token长度调节，较长评论单独计算。
- 使用BGE原生8192-token上限。正式数据实际最长3993 tokens，139条超过Pilot的512上限，均可完整编码。提高上限不改变Pilot短句的输入内容。
- 模型、分词器和依赖版本固定；离线加载已有权重，不微调、不调用在线推理。
- 评论文字是唯一编码特征。游戏、语言、推荐标志、作者和游玩时长不输入模型。

## 五步进度

1. 模型确定：已由用户选定BGE。
2. 小规模Pilot：两模型技术对照和用户近邻阅读完成；未虚构独立人工标签。
3. 全量向量：使用固定冻结文本生成缓存与ID映射；结果入口见 `output/embedding-bge/freeze_20261101-v1/run_summary.json`。
4. 聚类实验：留待下一阶段，先比较KMeans与层次聚类，观察规模、语言构成和代表文本。
5. 主题核验：继续保留多方面、表达风格与无明确主题的区别，安排成员核验后再冻结主题。

原数据语言标签与实际文字不一致的问题仍待正式审阅。它不妨碍多语言文本编码，但正式RQ3语言对比不能只信API标签。
