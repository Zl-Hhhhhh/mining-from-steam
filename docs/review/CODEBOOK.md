# 首轮人工主题核验：操作规则 v1

本规则用于任务11首轮独立核验，尚不是最终研究主题。两名标注者必须使用同一版；遇到新边界先标“不确定/其他”并写理由，不在中途私下商量某条正式样本的答案。

## 先逐条判断，再看候选组

阶段1共300条：原有250条共同样本保留，另50条补充中心、随机、边界和短文本。样本顺序不同，但A/B看到完全相同的评论。只看原文，不参考机器分组、推荐标签或另一位的答卷。可分多次完成，结束前导出JSON备份。

全部完成阶段1后导出完成JSON，再打开阶段2并导入本人阶段1文件解锁。阶段2有30个匿名候选组，分别包含一批中心/随机例子；独立给组命名、评判具体方面一致性，并记录合并/拆分/重做意见。阶段2不能反过来充当阶段1答案。提交两个完成JSON即可。

## 1. 实际文字语言

选英语、中文、混合、其他或无法判断。机器来源语言不展示。看不懂的语言可以选无法判断，方面选“不确定—看不懂语言”；不能因此判作没有主题。日语汉字不自动等于中文，纯符号也不应猜语言。

## 2. 是否有具体方面

- **有：** 能指出具体玩家关注点。允许很短；允许对一个方面正负混合；允许多个方面。
- **没有：** 只有泛赞/泛骂、纯符号、与游戏无关的内容，或纯梗且没有可指出的游戏方面。选择原因。
- **不确定：** 语言、语境、引用或表达不清，不能有把握判断。选择原因并写说明。不要把不理解混成“没有”。

不能只按字数区分。咒骂不自动等于无主题，玩梗也可能带有具体意见。这里判断的是“谈了什么”，不是是否推荐。

## 3. 方面标签：允许多选，每个标签需要原文证据

| 标签 | 纳入 | 边界与例子 |
| --- | --- | --- |
| 玩法与机制 | 核心循环、关卡、策略、探索、构筑等 | 泛泛说好玩不够；明确说战斗循环重复有方面 |
| 操作、难度与平衡 | 手感、按键、输入响应、学习门槛、难度、数值平衡 | 明确卡顿/FPS归性能；两者同时出现可多选 |
| 性能、稳定性与BUG | 帧率、卡顿、崩溃、无响应、兼容、进不去、技术BUG | 服务器网络技术问题也可选此项；同时谈联机环境可多选 |
| 剧情与角色 | 叙事、人物、故事表达 | 只写角色名或台词，若不清楚在评价什么则不强推 |
| 画面、美术、音乐与音效 | 视听表现及风格 | 本轮合并为一个方面，可在备注建议拆分 |
| 联机、匹配、作弊与社区 | 合作、对战、匹配、外挂、玩家互动、社区 | 骂人不必然是社区问题，须有相关上下文 |
| 价格、付费与DLC收费 | 价格是否划算、内购、收费公平、购买成本 | DLC内容量归内容；同时谈收费可两项都选 |
| 内容量、重玩、MOD与更新维护 | 内容多少、重复游玩、模组、更新支持等 | 更新引发闪退可另选性能；只说“更新后玩不了”主要有性能证据，不因有更新二字自动多选 |
| 其他具体方面 | 以上不能合理容纳但有明确证据的关注点 | 备注提出新名称，不能把所有模糊内容塞到此项 |

尽量直接复制原文短语作为每个标签的证据。长评可能涉及很多方面；不要为了贴合某个机器簇只选一个。某个词出现不必然构成方面证据，应看句意及勾选状态。

## 4. 表达方式：与方面独立

普通表达选“普通”；有可识别特殊表达时多选标记；拿不准时选表达方式不确定并说明。标记包括咒骂词、针对特定对象的攻击、梗/引用、疑似反讽线索、文言/仿古、emoji参与、打分/勾选模板。

咒骂与攻击区分：`fucking laggy`有咒骂且谈性能；是否攻击特定人要有对象。反讽只记“疑似线索”，不要断言作者真实心理。文言只记表达形式，不要求把整条另分为文言主题。模板须区分勾选和未勾选选项：未勾选的“画面差/音乐好”等不算作者意见，无法确定符号含义时写不确定。

## 5. 练习例子（人为构造，仅用于理解规则）

1. `太卡了。` → 有：性能；普通表达。证据“太卡了”。
2. `非常好玩！` → 没有具体方面：泛评。不能仅凭好玩就选玩法。
3. `剧情很好，但经常闪退。` → 剧情＋性能；两段证据分别填写。
4. `全是挂。` → 有：作弊/联机环境；很短也有信息。
5. `优化真好，五分钟闪退三次。` → 有性能证据；可标疑似反讽线索，不靠正话反说猜全部情绪。
6. `画面真漂亮😍` → 有视听方面；emoji参与表达。
7. `👍👍👍` → 没有可确认的具体方面：纯符号；表达含emoji。语言无法判断不影响此处可见信息的判断。
8. `☐画面差 ☑画面好 ☐音效差` → 视听方面，证据为勾选的“画面好”；模板标记，未选项不当作意见。
9. `这个DLC内容太少，卖这个价格不值。` → 内容＋价格，各有证据。
10. 不懂的外语或只剩无法解释的引用 → 方面不确定，记录原因。不要填无主题来凑完成。

这些答案不是正式300条的预标注。正式样本没有任何机器或AI标签供照抄。

## 6. 阶段2：候选组独立命名

每组有中心和随机例子。先给性质：单一具体方面、多方面、泛评、混杂难解释或不确定。再给“具体方面一致性”评分：

- **0：** 找不到一致的具体方面，或主要为泛赞/泛骂/杂项。
- **1：** 有部分共同关注点，但混入其他内容或边界不清。
- **2：** 多个中心及随机例子共同支持较一致的具体方面；仍要记反例。

可命名为“无具体方面/泛赞”“无法解释的混杂组”，不要求每组都有正式主题。独立建议合并、拆分或重新训练，并引用E编号说明。不同G编号可以语义相近；编号没有研究含义，也不保证来自同一种方法。不能因为例子同为中文或同为好评就认为具体方面一致。

## 7. 保存、疑难与交回

页面仅在本机工作，不需要Python、不联网、不登录、不上传。每次离开前导出JSON备份；重新打开可导入本人的备份。规则和标注者代号确认后，全部项目有效才可导出完成JSON。CSV只是阅读副本，正式汇总读JSON。

阶段1和阶段2分别交回一个完成JSON。两个人都完成后才比较答案、处理分歧。若发现规则有共同歧义，先各自留不确定和备注，由协调人统一记录；需要改版时应对两人都生效，不只改其中一人的答案。

这批样本用于解释核验和方法改进，不是总体主题比例或独立留出准确率测试；最终主题、合并拆分和模型不确定范围仍要结合人工结果决定。
